## 1. 项目是什么

**一个纯前端的个人记账 PWA**：记一笔（含凭证照片）、明细、图表、预算洞察、多账本、CSV/JSON 导入导出、可选的云备份与多设备账号同步。

三条贯穿始终的设计原则，读懂它们就读懂了所有代码的"为什么"：

1. **本地优先（Local-first）**：数据的第一存档永远是设备本地（IndexedDB），云端只是加密镜像。断网全功能可用，云只是锦上添花。
2. **零信任云端**：凡是离开设备的数据（云备份/账号同步）都先在客户端加密（PBKDF2 60万轮 + AES-256-GCM），服务器只存密文。
3. **永不丢数据**：所有同步合并策略都是"并集 + 同条取较新"，任何一端都不会被静默覆盖。

版本：v1.6.1（2026-08）。技术栈：Vite 5 + React 18 + TypeScript(strict) + TailwindCSS + Zustand + Chart.js + idb + Supabase，GitHub Pages 自动部署。

## 3. 核心概念（读代码前先记住这五件事）

### 3.1 金额一律整数「分」

`amountCents: number`，全项目没有任何地方用浮点存金额。展示时 `money.toYuan()`（1250 → "12.50"），
输入时 `parseYuanToCents()`（"12.5" → 1250）。这消除了 `0.1 + 0.2 ≠ 0.3` 一类的经典浮点灾难。

### 3.2 三级存储降级

`probeStorage()` 启动时依次探测：**IndexedDB → localStorage → 内存**，结果写入 `repo.mode`。
Safari 私密模式（IDB 不可用）自动降级，UI 顶部横幅提示"数据仅存内存，请导出备份"。所有上层代码
只跟 `repo` 说话，永远不感知后端是谁。

### 3.3 单一数据仓库 + 引用稳定化

`repo.ts` 是唯一的数据出入口：启动时把 IDB 全量读进内存缓存，此后**所有读走内存（O(1)），
所有写先改内存再异步落盘**。`store/data.ts` 的 `sync()` 把 repo 缓存映射进 Zustand，
并做逐项比较的**引用稳定化**——没变化的表复用旧数组引用，让 React.memo/selector 订阅精准跳过无关重渲。

### 3.4 语义 Token 主题体系

全项目禁止硬编码颜色。`index.css` 定义 `--surface/--card/--fill/--line/--ink/--primary…`，
Tailwind 映射成 `bg-card`、`text-ink-2` 等类。**暗色模式 = 换一组变量值**，不是逐组件打补丁；
图表取色也走 `getComputedStyle` 读变量，主题天然一致。当前皮肤：暗色金融风（深炭 + 香槟金）。

### 3.5 渲染性能预算

- 页面级懒加载：非首屏路由全部 `React.lazy`；supabase-js（218KB）独立分包且移出 SW 预缓存
- 订阅粒度：组件全部用 selector 订阅单个字段，禁止整 store 订阅
- 长列表：账单行 `content-visibility: auto`（视口外跳过布局绘制）+ `memo` 行组件 + 稳定回调
- 全局 `font-variant-numeric: tabular-nums`：金额数字等宽对齐

## 4. 一次"记一笔"的完整数据流

以"支出 12.5 元、餐饮、备注、拍照、微信支付"为例：

```
EntrySheet（面板 UI）
  ├─ NumberKeyboard 输入 "12.5"（自绘键盘，不唤起系统输入法）
  ├─ 选分类 / 选账户（微信）/ 填备注 / 选照片
  │     └─ 照片：compressImage() 压成 ≤1280px JPEG → repo.putPhoto() 先落 IDB photos 表
  ▼ save()
  1. 校验金额/分类 → repo.putPhoto() 拿到 photoIds（失败重试有 storedId 防重复入库）
  2. store.addBill() 组装 Bill{ id, amountCents:1250, categoryId, accountId, photoIds, … }
  3. repo.upsertBill()：改内存缓存 → IDB put → commit()（BroadcastChannel 通知其他标签页 + onChange）
  4. data.sync()：引用稳定化后更新 Zustand → 只有订阅了 bills 的组件重渲
  5. scheduleSync()：5 秒防抖
       ├─ manager.doSync()      （Gist/WebDAV 备份，若配置）
       └─ account.scheduleVaultSync()（登录用户：整库快照 → 客户端加密 → upsert 云端 vaults 表）
  6. UI toast「已记一笔」，面板关闭；明细列表新增一行：餐饮 / 备注（微信）/ -12.50
```

删除走**软删除**：`deletedAt` 打标记进 30 天回收站，到期 `purgeBill()` 物理删除并连带清理照片。

## 5. 存储层（`src/db/`）

**schema.ts** — `SCHEMA_VERSION = 2`，7 张表：`bills`(索引 byUpdated)、`categories`、`accounts`、
`tags`、`ledgers`、`budgets`(keyPath yearMonth)、`meta`、`photos`(v2 新增，索引 byBill)。
`openLedgerDB` 的 upgrade 全部用 `objectStoreNames.contains` 判断，**老库升级自动补建新表，不迁移数据**。

**repo.ts** — 关键方法速查：

| 方法 | 作用 |
|---|---|
| `init()` | 探测存储 → 全量读入内存 → 数据迁移 → 种子 → 清理 30 天过期软删除 → 开 BroadcastChannel |
| `upsertBill()` | 写内存 + 差异清理被移除的照片 + IDB put + commit |
| `insertBills()` | 批量合并去重（演示数据/导入），单事务落盘只广播一次 |
| `replaceAll()` | 恢复/同步用：overwrite（整库采用）或 merge（`mergeDumps`） |
| `setMeta/getMeta` | 小型 KV（currentLedgerId、lastSyncAt、schemaVersion…） |
| `putPhoto/loadPhotoURL` | 照片 Blob 存取 + objectURL 会话缓存（上限 300 条 LRU 式清理） |

**跨标签页一致性**：每次写操作 `commit()` → `postMessage('changed')`；其他标签页收到后
**250ms 防抖**全量 `reload()`（消息风暴合并为一次读取）。回前台另有 5 秒节流的全量刷新兜底。

## 6. 云同步的两条通道（互相独立）

### 6.1 Gist / WebDAV 备份（v1.0 起，文件级）

配置存在 meta，内容 = `buildBackupFile()` 生成的整库 JSON（可选 AES-GCM 加密），单向 push。
轻量但**不解决多设备并发覆盖**（TODO：引入 pull→merge→push）。

### 6.2 Supabase 账号同步（v1.5 起，账号级）

- **认证**：邮箱+密码走 GoTrue（服务端散列），会话持久化 + 自动刷新
- **存储**：`vaults` 表每用户一行（`cipher` 列），**RLS 四条策略**保证只能读写自己的行
- **同步算法**（`syncVault()`）：

```
拉取云端 cipher → (有口令则解密) → validateDump 校验
本地 bills 为空（新设备）→ 整体采用云端（避免种子分类与云端重复）
否则                     → mergeDumps(local, cloud)：id 并集、同 id 取 updatedAt 大者
合并结果落本地 → fullDump → (口令加密) → upsert 回云端
```

两端数据都保留，后写者胜出于单条记录级别。触发时机：登录成功、写操作后 5s 防抖、网络恢复。
未配置 `VITE_SUPABASE_URL/ANON_KEY` 时整条链路按需加载且 UI 隐藏——**应用行为与无账号时代完全一致**。

### 6.3 凭证照片为什么不上云

照片是 Blob（单张 ~200KB），而两条云通道都是 JSON 载体（Gist 有 1MB 级限制、账号表存 text）。
强行 base64 会让备份膨胀数十倍。取舍：照片仅存本机，账号页明确提示"照片不参与同步"；
跨设备迁移照片列为未来可选的二进制备份通道（R2/WebDAV 直传 zip）。

## 7. UI 层要点

- **布局骨架**：`#root` 高度 = `--app-height`（JS 兜底 dvh）。页面内部各自 `overflow-auto`，
  **document 永不滚动**——这是所有键盘/安全区兼容处理的前提
- **键盘三件套**（iOS 深坑集）：
  1. 输入类元素 iOS 下统一 16px（`@supports (-webkit-touch-callout: none)`），否则聚焦自动放大页面
  2. `--app-height` 忽略键盘导致的视口骤缩（>12% 视为键盘），布局保持不动
  3. `Sheet` 面板监听 `visualViewport.resize`，把自己抬到键盘上方（bottom = 键盘高度）——
     输入框始终可见，iOS 便不会平移视口，消除"呼出键盘闪一下"
- **浮层误触三防**（`Sheet` 内建）：
  1. 入场冷却 300ms：面板滑入期间 `pointer-events:none` + 遮罩点击忽略——双击加号的第二击
     不再砸进键盘误输入（FAB 正下方就是"0"键）或秒开秒关
  2. 退场屏蔽 280ms：关闭后短暂透明层吞掉余触，不穿透到底下的 FAB/账单行
  3. `overscroll-behavior: contain`：面板内滚动到头不把手势链给底层页面
- **TabBar**：悬浮磨砂玻璃栏（backdrop-blur + 88% 玻璃底）。FAB 必须是玻璃栏的**兄弟节点**
  （绝对定位上探出栏体 + `will-change: transform` 独立合成层，按压缩放不重绘）——
  `backdrop-filter` 容器会把带 transform 的合成子元素裁进圆角盒（FAB 上半截/加号图标
  偶发缺失的根源），做子元素必裁
- **Sheet 光栅化**：入场动画期间提升独立合成层，动画结束即摘除动画类强制静止态整层重绘——
  规避 WebKit「transform 动画 + 圆角 + overflow 滚动容器」逐瓦片重光栅化造成的图标缺角
- **长按删除**：`onTouchStart` 500ms 计时 + `onTouchCancel`/卸载清理，同步刷新行消失不误弹

## 8. 构建与部署

```bash
npm run dev        # 本地开发（Vite，:5173）
npm run build      # tsc --noEmit + vite build（含 PWA 产物）
npm run preview    # 预览构建产物（:4173）
npm run icons      # 重新生成 PWA 图标
git push origin main  # 触发 GitHub Actions → 自动构建 → 部署 Pages
```

- **部署**：`.github/workflows/deploy.yml`，push main 即部署；Supabase 配置经 Actions Secrets 注入
- **PWA**：vite-plugin-pwa，`prompt` 更新模式（应用内横幅"检测到新版本"）。
  预缓存排除两个大块：Chart.js（208KB）与 supabase-js（218KB）——多数用户首装少下载 400KB，
  访问对应功能后由运行时缓存（CacheFirst）接管离线
- **CSP**：构建时注入 `Content-Security-Policy`（img-src 含 blob: 支持照片缩略图，connect-src https: 放行自配后端）
- **环境变量**：`VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`（本地 `.env.local`，线上 Secrets）

## 9. 关键设计决策备忘（为什么不是别的方案）

| 决策 | 理由 |
|---|---|
| 整数分而非小数元 | 浮点误差在账本场景不可接受 |
| 整库快照同步而非逐条 delta | 数据量级下最简单、原子、无丢数据路径；`byUpdated` 索引为未来增量预留 |
| Supabase 而非自建后端 | 纯静态托管（GitHub Pages）无服务端；认证/RLS/免费额度开箱即用 |
| 照片仅本地 | JSON 备份通道装不下 Blob；收益/复杂度比不划算 |
| 状态管理层用 Zustand 而非 Redux | 体量小、selector 订阅天然贴合"引用稳定化"策略 |
| 自绘数字键盘 | 金额输入全程可控（不唤起系统键盘 → 无缩放/无第三方键盘干扰） |
| 兼容 iOS 而非抽象掉它 | 目标用户主力是 iPhone；键盘/安全区/dvh 是 PWA 与原生体验差距的全部来源 |

## 10. 已知限制与路线图

**限制**：Gist/WebDAV 通道多设备并发会整文件覆盖（账号通道已解决）；照片不跨设备；
iOS 主屏 PWA 第三方键盘可用性受系统限制；iOS Safari 聚焦小字号输入会缩放（已用 16px 规避）。

**路线图**（按 ITERATION_LOG 待办）：Gist/WebDAV 通道引入 pull→merge→push；照片二进制备份通道；
标签系统（`tags`/`tagIds` 字段已就绪）；多币种；周期记账；资产管家；
`mergeDumps`/`validateDump`/`compressImage` 补 vitest 单测。
**鲨鱼 Pro（VIP）**：见 `docs/VIP功能方案.md`——P1 权益层/无限账本/年度报告 与 P2 照片云同步已落地；
P3 AI 分析待定 API 成本；免费核心功能永远不动。
