# 鲨鱼记账 · 付费模式方案（买断制）

> 本文档是付费/增值功能的唯一事实来源。最后更新：v1.8.1（2026-08-30）。

---

## 0. 产品决策（2026-08-30 定稿）

**一次性买断制**：如果上架 iOS App Store，定价 **¥6 一次性购买，永久解锁全部功能**（非消耗型内购）。不搞订阅、不搞年费、不做兑换码门槛。

**当前阶段（开发者自用 + 打磨期）**：**所有功能开箱即用、全部免费**——账本不限量、年报直接看、照片云同步登录即用。应用里不存在任何"升级/解锁"弹窗和锁标。

理由：现阶段核心目标是把产品打磨到值得被购买；付费墙是上架前最后一步才做的事，且在 App Store 里由系统内购承担，前端无需自建门槛。

## 2. 上架 App Store 时的接入清单（未来）

1. App Store Connect 创建非消耗型内购项（¥6，名称如"解锁鲨鱼记账高级版"）。
2. App 内接 StoreKit 2（需原生壳或 Capacitor 等容器，PWA 无法直接调 IAP）。
3. 购买成功 → 收据校验 → `usePro()` 返回 `true` 并本地持久化（恢复购买按钮必做）。
4. 未购买用户：功能可试用 or 直接锁（到时候再定，UI 层只需恢复 ProGate 组件——git 历史 v1.8.0 里有完整实现）。

## 3. 兑换码体系（已部署、前端停用，作为备用通道存档）

> 以下 SQL 已于 2026-08-30 在项目数据库执行（`deploy/supabase-vip.sql`），表与函数保留。
> 前端 v1.8.1 起不再有任何入口。适用场景：不走 App Store 的渠道（官网直售、朋友代购）时，
> 可随时用 `select gen_license('yearly', 365, '备注');` 发码 + 前端临时恢复兑换入口启用。

### 3.1 数据库对象

- `licenses`：兑换码池（码 / 套餐 / 天数 / 绑定用户），RLS 开启且无客户端策略，只能经 RPC 操作
- `pro_entitlements`：用户权益（plan / expires_at，lifetime 为 null = 永久），RLS 仅本人可读
- `redeem_license(p_code)`：SECURITY DEFINER 兑换函数（校验 → 绑定 → 写权益，续费自动顺延）
- `gen_license(plan, days, note)`：生成 `SHARK-xxxx-xxxx` 格式的码
- Storage 私有桶 `photos` + 按用户目录隔离策略（**照片云同步正在使用，不停用**）

### 3.2 测试码清理（正式运营前）

```sql
delete from licenses where code like 'SHARK-TEST-%';
```
